# 3D mesh extent check (D4)

See also: [3D-MODELS.md](3D-MODELS.md) (status and sources), [IFC.md](IFC.md) (semantic reader).

## What is measured
`app/design/mesh_reader.py` streams the 303 MB IFC `12100-RCRV-199_07-08-2021.ifc` as text (no geometry kernel). It reads every `IfcCartesianPointList3D`, takes its min/max, applies the element's `IfcLocalPlacement` chain and returns the overall bounding box as one `ship_extent` element (`length_overall`, `beam`, `height`, in mm; provenance `method="mesh"`, confidence 0.6). The result is cached in `.cache/` (git-ignored) by file size and mtime.

Runtime on the real file: about 4 s cold, instant when cached. 84,581 parts with geometry were used.

`app/design/particulars_text.py` reads labelled values (label spellings in `app/design/particulars_labels.json`) from a PDF text layer. `app/design/cross_check.py` compares both sides:

```bash
python -m app.design.cross_check ~/Downloads/12100-RCRV-199_07-08-2021.ifc Files/rcrv-particulars.pdf
```

Within the tolerance (default 10 %) the finding is `pass`; outside it, or when a stated value is missing, it is `needs_review`. It is never `fail`, because the box includes masts and appendages. Each finding cites the mesh and the PDF line (page, bbox, quote).

## Real numbers
Mesh as declared by the file (IFC says millimetres):

| | mesh | stated, particulars PDF | stated, design summary report |
|---|---|---|---|
| length overall | 2,626 mm | 199.5 ft = 60,808 mm | 192' 10" = 58,776 mm |
| beam | 762 mm | 50 ft = 15,240 mm (overall) | 50' 2" = 15,291 mm |
| height | 1,116 mm | draft 12.5 ft + air draft 88.5 ft = 30,785 mm | air draft not stated |

They do not agree: the mesh is about 4.3 % of the stated length. All three cross-check findings are `needs_review`.

The mesh has a coherent ship-like shape (length : beam : height = 3.4 : 1 : 1.5), so the likely cause is a unit mismatch in the export, not a wrong model. If one mesh unit were one inch (a hypothesis, not applied anywhere), the extents would be 66.7 m x 19.4 m x 28.3 m, which is 1.10x, 1.27x and 0.92x the stated values. That is plausible for a box that includes cranes, A-frame and masts, but it is not proof. Someone has to confirm the unit with the model's author.

The two PDFs also disagree with each other (LOA 199.5 ft vs 192' 10").

## What is not measured / limits
- Bounding box only: masts, antennas, cranes and A-frame are included, so it is not length overall of the hull.
- Length is the larger horizontal extent (X or Y); there is no heading metadata. Height is Z.
- The unit is taken from the IFC header and is never corrected. Mapped items and swept solids are not read (this file has only triangulated face sets). Unreferenced points in a list count too.
- No outlier filtering; the percentile check showed no isolated far-away parts, but stray geometry would inflate the box.
- Stated values are only read where a label, a number and a unit are all present.
